### Этап 1: Инфраструктура и Данные (Foundation)

_Готовим фундамент, на котором будет крутиться вся логика._

1. **Инициализация окружения (Сделано)**
    
    - Поднятие `SurrealDB` и `MinIO` через Docker Compose.
        
    - Настройка `Air` для горячей перезагрузки Go-кода.
        
2. **Проектирование схемы данных (SurrealQL)**
    
    - Описание таблиц: `university`, `specialty`, `subject` (предметы ЕНТ).
        
    - Описание графовых связей: `university -> offers -> specialty` (с полями грантов и проходных баллов).
        
    - Создание полнотекстовых индексов для поиска.
        
3. **Настройка хранилища (MinIO)**
    
    - Создание бакетов `logos` и `documents`.
        
    - Настройка политик доступа (Read-Only для паблика).

### Этап 2: Ядро Бэкенда (Go Core & Services)

_Пишем движок: подключение к базе, хранилищу и базовую логику._

1. **Архитектура проекта и Конфиги**
    
    - Настройка роутера (Fiber).
        
    - Парсинг переменных окружения (БД, S3, секреты).
        
2. **Слой Data Access (Репозитории)**
    
    - Инициализация официального Go-драйвера SurrealDB.
        
    - Написание базовых CRUD-операций для вузов и специальностей.
        
3. **Сервис Хранилища (S3)**
    
    - Интеграция `minio-go`.
        
    - Логика загрузки картинок (генерация UUID, загрузка, возврат URL).
        
4. **Аутентификация для Админки**
    
    - Реализация Session-based авторизации на куках (для HTMX куки работают идеально из коробки, в отличие от JWT в заголовках).
        
    - Middleware для защиты `/admin/*` роутов.

### Этап 3: Админ-панель (Go Templates + HTMX)

_Делаем интерфейс для управления данными без единого грамма JS-фреймворков._

1. **Скелет интерфейса**
    
    - Настройка парсинга шаблонов `html/template` в Fiber.
        
    - Подключение Tailwind CSS (через Standalone CLI, чтобы не тащить Node.js/NPM в проект).
        
    - Подключение HTMX через CDN (или скачанный скрипт).
        
    - Создание `layout.html` и папки `partials/` для компонентов.
        
2. **Управление Вузами (CRUD)**
    
    - `GET /admin/universities` — рендер таблицы со списком вузов.
        
    - Форма создания вуза: отправка через `hx-post`, валидация на бэке, добавление строки в таблицу без перезагрузки страницы (`hx-swap`).
        
    - Загрузка логотипа: нативный `<input type="file">`, обработка в Go, сохранение в MinIO, обновление превью через HTMX.
        
3. **Управление Специальностями (Графы)**
    
    - Интерфейс привязки специальностей к вузу (создание связей `offers` в SurrealDB).
        
    - Инлайн-редактирование: клик по ячейке с баллами ЕНТ -> появление инпута -> сохранение по Enter (`hx-trigger="keyup[key=='Enter']"`).

### Этап 4: Публичный JSON API (Для будущего фронта)

_Готовим чистые эндпоинты, к которым потом присосется клиентский микросервис._

1. **Read-Only Эндпоинты**
    
    - `GET /api/v1/universities` — список с пагинацией и фильтрами.
        
    - `GET /api/v1/universities/:id` — карточка вуза.
        
2. **Поисковый движок**
    
    - Реализация эндпоинта подбора вузов: на вход два предмета ЕНТ -> графовый запрос в SurrealDB -> JSON-ответ с подходящими специальностями и грантами.
        
3. **Оптимизация API**
    
    - Настройка Rate Limiting для публичных роутов.
        
    - Кеширование частых запросов (опционально, можно поручить Fiber'у).
        

---

### Этап 5: Деплой (Production Ready)

_Упаковка всего этого в монолитный, не требующий обслуживания танк._

1. **Сборка**
    
    - Написание единого `Dockerfile` (multistage), который компилирует Go-бинарник и пакует в него HTML-шаблоны (через `go:embed`).
        
2. **Инфраструктура**
    
    - Написание `docker-compose.prod.yml` (App + SurrealDB + MinIO + Caddy).
        
    - Caddy сам разрулит HTTPS для API и Админки.
        
3. **Бэкапы**
    
    - Скрипт дампа SurrealDB и автоматическая отправка архива в приватный бакет MinIO.
        

---

**Резюме:** Мы имеем Go-монолит. Он сам рендерит свою админку (быстро и без JS-боли) и параллельно торчит наружу чистым JSON API для будущего фронтенда.
